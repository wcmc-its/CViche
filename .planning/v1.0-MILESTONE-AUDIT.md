## Integration Issues

### Issue 1 — CRITICAL: v1.0.0 tag is 20 commits behind HEAD (VER-02)

The v1.0.0 annotated tag was placed at commit `3bec79a` at the end of Phase 2. All Phase 3 work (20 commits: LICENSE, CHANGELOG, README, sample CV, screenshots, `__version__`) was committed after the tag. A user checking out v1.0.0 or cloning at that tag gets none of the Phase 3 documentation.

**Fix:** `git tag -d v1.0.0 && git tag -a v1.0.0 -m "v1.0.0 - Initial public release" HEAD`

**Affected:** VER-02, DOC-01, DOC-02, DOC-03, VER-01, VER-03, TEST-01

### Issue 2 — MODERATE: README CLI examples use real faculty UID (DOC-01)

README.md lines 71, 74, and 77 use `2097_Upton_Cv` — a real person's name from a production CV. This file is gitignored and absent from a fresh clone. The synthetic sample `sample_vasquez_cv` exists precisely to replace such references.

**Fix:** Replace all three `2097_Upton_Cv` occurrences with `sample_vasquez_cv`

**Affected:** DOC-01

### Issue 3 — LOW: Inconsistent API key variable name (DOC-01)

The README's Configuration section (line 57) instructs `export OPENAI_API_KEY=your-key-here`, but the codebase checks `OPENAI_API_KEY_WORK` first with `OPENAI_API_KEY` as fallback. The Docker section correctly names `OPENAI_API_KEY_WORK`. Functional today due to fallback, but inconsistent.

**Fix:** Update README line 57 to use `OPENAI_API_KEY_WORK` and note that `OPENAI_API_KEY` also works

**Affected:** DOC-01
