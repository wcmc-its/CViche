## Spacing Scale

Declared values (Tailwind default scale, multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps (`gap-1`), inline padding (`px-1`, `py-1`) |
| sm | 8px | Compact element spacing (`gap-2`, `p-2`, `mb-2`) |
| md | 16px | Default element spacing (`p-4`, `gap-4`, `mb-4`) |
| lg | 24px | Section padding (`p-6`, `gap-6`) |
| xl | 32px | Card padding on larger screens (`p-8`, `sm:p-5` expanded) |
| 2xl | 48px | Major section breaks (`p-12` in empty states) |
| 3xl | 64px | Not currently used |

Exceptions: none -- standard Tailwind spacing utilities only.

**Preservation rule:** When extracting `StatusIcon` to `src/components/shared/StatusIcon.tsx`, icon sizing MUST remain `w-4 h-4` (16px). When extracting formatting utilities, no layout or spacing classes move into utility functions -- utilities return raw strings/numbers only.

## Typography

| Role | Tailwind Class | Size | Weight | Line Height |
|------|---------------|------|--------|-------------|
| Body | `text-sm` | 14px | `font-normal` (400) | 1.43 (Tailwind default) |
| Label | `text-xs` | 12px | `font-semibold` (600) | 1.33 (Tailwind default) |
| Heading | `text-lg` | 18px | `font-semibold` (600) | 1.56 (Tailwind default) |
| Display | `text-2xl` | 24px | `font-semibold` (600) | 1.33 (Tailwind default) |

Declared weights: `font-normal` (400) for body text, `font-semibold` (600) for all emphasis tiers (labels, headings, display, buttons).

**Existing `font-bold` (700) note:** The codebase uses `font-bold` on 9 elements: 3 stat numbers (`text-2xl` in AdminDashboard, AdminFeedbackInsights, PipelineViewer), PipelineHeader h1, JsonViewerModal h2, and ConsentPage h1-h4. These are existing usages that this refactoring phase does NOT modify -- they remain `font-bold` in their component files. The design contract declares the 2 dominant weights (400, 600) that govern 95%+ of text rendering. The `font-bold` occurrences are a legacy emphasis pattern confined to specific components and are not part of the extractable design token system.

Source: grep of all component files. The codebase uses exactly these 4 size tiers consistently.

**Preservation rule:** The `StatusIcon` component and `statusLabel`/`statusLabelColor` utilities are consumed by components that apply their own typography classes. Extracted utilities MUST NOT embed font-size or font-weight classes -- the calling component controls text styling.

## Formatting Utility Contract

These utilities are extracted from duplicated implementations into `src/utils/format.ts`. Each function's output format is specified here as the contract.

### `formatDate(dateString: string): string`

| Context | Input Example | Output | Format Spec |
|---------|--------------|--------|-------------|
| Run tables (RunHistory, AdminSubmissions) | `"2026-03-26T14:30:00Z"` | `"Mar 26, 2:30 PM"` | `month: 'short', day: 'numeric'` + `hour: '2-digit', minute: '2-digit'` |
| Admin user lists | `"2026-03-26T14:30:00Z"` | `"Mar 26, 2026"` | `month: 'short', day: 'numeric', year: 'numeric'` |

Decision: Export two functions -- `formatDate(dateString)` for date+time (run tables), `formatDateShort(dateString)` for date-only (admin user lists). This avoids a boolean flag parameter.

### `formatDuration(seconds: number | null): string`

| Input | Output | Rule |
|-------|--------|------|
| `null` | `"\u2014"` (em dash) | Null/undefined returns em dash |
| `45` | `"45s"` | Under 60 seconds: `{s}s` |
| `125` | `"2m 5s"` | 60+ seconds: `{m}m {s}s` |
| `120` | `"2m 0s"` | Exact minutes still show seconds |

### `formatCost(cost: number, precision?: 2 | 3): string`

| Context | Input | Precision | Output |
|---------|-------|-----------|--------|
| Summary views (RunHistory, AdminUsers, AdminDashboard) | `1.234` | 2 | `"$1.23"` |
| Detail views (PipelineViewer, PipelineHeader, StepSidebar, AdminSubmissions) | `0.0456` | 3 | `"$0.046"` |

Decision: Default precision is 2. Detail views pass `3` explicitly. Always prefix with `$`.
