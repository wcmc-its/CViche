Pre-Upload Consent Flow

How should the consent form integrate into CViche? The form captures: project description, name, email, authorization role, consent checkbox, then file upload.

A

Modal Before Upload

User clicks "Upload CV" → consent modal appears with all fields (name, email, role, consent checkbox). On submit, modal closes and file picker opens. Consent is logged to DB with timestamp. Returning users see a shorter "Welcome back" modal confirming their info.

Pros

  • Self-contained — no external Qualtrics dependency
  • Data stored locally for your paper
  • Can pre-fill for returning users
  • Consent tied directly to each run

Cons

  • Must maintain consent text yourself
  • IRB may need to approve the new format
B

Integrated First-Run Page

First-time users land on a consent page (not a modal — a full page) before seeing the upload UI. They fill out name, email, role, consent. After consenting, they're taken to the upload page. Returning users skip straight to upload (consent on file).

Pros

  • More prominent — feels like a proper onboarding step
  • Can't be accidentally dismissed
  • One-time per user (less friction for repeat use)

Cons

  • More complex routing
  • Consent may need renewal for new IRB periods
C

Hybrid: Consent Page + Per-Run Confirmation

First visit: full consent page with all fields. Each subsequent upload: a brief one-click confirmation ("I confirm this CV submission is authorized"). Best of both — thorough initial consent, lightweight repeat confirmation.

Pros

  • Strongest paper trail — consent per user AND per run
  • Returning users aren't blocked, just one click
  • IRB-friendly: initial consent + ongoing acknowledgment

Cons

  • Slightly more friction per run
