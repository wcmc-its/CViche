CViche Production Architecture

Full system design — 7 subsystems. Review each section and let me know if anything needs adjustment.

1. Authentication & Identity

Auth Flow
Phase B (Now)
• Simple email-based identity
• User enters name + email on first visit
• Session stored in httpOnly cookie
• Allowed users defined in config.yaml
• Admin flag in config
→
Phase A (Later)
• SAML SSO via Janus / WCM IdP
• User identity from SAML assertion
• Group membership from Enterprise Directory
• Same session cookie, different auth backend
• Auth backend is a swappable module

2. Data Model Changes

New: User table
  id, email, display_name, role (user|admin),
  status (active|disabled), daily_limit, monthly_limit,
  consent_version, consent_date, created_at, last_active_at

New: Consent table
  id, user_id, consent_version, consent_text_hash,
  ip_address, user_agent, timestamp

New: FeedbackStatus table
  id, run_id, user_id, feedback_given (bool),
  qualtrics_clicked_at, marked_complete_at

Modified: Run table
  + user_id (FK → users), + submitter_role (own_cv | authorized_admin)

3. Consent Flow

First visit: Full-page consent form
• Project description (from your Qualtrics form text)
• Name & email (pre-filled if SAML)
• Authorization role: "Submitting my own CV" / "Authorized admin"
• Consent checkbox with timestamp logged
• Consent text is versioned — if you update it, users re-consent on next visit

Returning visits: Straight to upload page (consent on file)

Storage: Consent record in DB with text version hash, timestamp, user agent. Exportable for your paper.

4. Rate Limiting

Defaults: 10 runs/day, 50 runs/month per regular user
Admins: Unlimited
Per-user override: Admins can adjust limits via dashboard
Enforcement: Backend middleware checks before accepting upload
UI: Upload page shows remaining quota. When limit hit, upload button disabled with explanation.

5. Feedback Nudging

Completion Interstitial
When a run finishes: full-screen overlay with Download button + "Share Feedback" button (equal prominence). "I'll do this later" dismisses.
Run History Badges
Persistent amber banner: "N runs awaiting feedback." Each run shows "Needs feedback" or "Feedback given" badge. Banner can't be dismissed — clears when all caught up.
Feedback tracking: we log when user clicks the Qualtrics link. User can also mark "feedback given" manually (in case they complete it in a separate tab).

6. Run History & Pagination

• Show 20 runs initially, "Show more" button loads 20 more
• Each run shows: filename, status icon, date, duration, cost, feedback badge
• Clicking a completed run → view results (read-only pipeline viewer)
• Clicking a failed/cancelled run → read-only view + "Restart with this file" button
• Users see only their own runs
