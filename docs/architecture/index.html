CViche — Architecture

CViche turns an unstructured academic CV (Word .docx) into a standardized Weill Cornell Medicine CV. A 12-stage LLM pipeline segments the document, extracts and classifies entries against the WCM taxonomy, enriches publications via PubMed/ROR, and renders the WCM Word template. It runs from a CLI or a FastAPI + React web app with live progress over WebSocket.

System context

CViche standardizes academic CVs into the Weill Cornell Medicine format. Two entry points drive the same 12-stage pipeline: a CLI for batch runs and a React + FastAPI web app for interactive use. The pipeline calls an LLM provider (AWS Bedrock by default, OpenAI as an alternative) for ten of its twelve stages, enriches publications via PubMed, and persists runs and artifacts to a database and object store.

View 2 · processing pipeline

The 12-stage CV pipeline

Each stage produces JSON the next stage consumes, grouped into six phases. Ten of the twelve stages call an LLM (AWS Bedrock Claude — Sonnet 4.6 by default; stage 3b runs the cheaper, gold-eval-preferred Haiku 4.5). The two exceptions: 1b (header→index mapping) is deterministic, and 5 (PubMed enrichment) calls an external API. Stage 6's headline job is rendering the WCM Word document — the pipeline's primary output — but it also calls the LLM to classify the geographic scope of presentations and service.

View 3 · web app & run lifecycle

Web app & run lifecycle

The browser uploads a CV (creating a run + 12 step rows), then starts it. Start passes a per-pod admission gate (CVICHE_MAX_CONCURRENT_RUNS; full → HTTP 429) and schedules an in-process asyncio background task that runs the orchestrator — the API returns immediately. Progress reaches the browser two ways: it polls status every 2 s and subscribes to a WebSocket fed by step events (a Redis broker carries them across pods when replicas > 1). When the run finishes, the browser downloads the WCM document.

View 4 · deployment topology

Deployment topology (EKS)

Kustomize renders a base + prod overlay into namespace cviche-prod on EKS. An ALB Ingress terminates TLS for cviche.weill.cornell.edu and routes /api + /ws to the backend Deployment and everything else to the frontend. In prod the backend runs 2 replicas (2 vCPU / 2Gi each) under an HPA (CPU 70%, 2–4 pods); it reaches Bedrock through an IRSA ServiceAccount and reads MariaDB + S3. Auth config, SAML certs, and DB secrets are mounted from a ConfigMap and Secrets.
